## 3. Decisions locked + what shipped

**Two defects, neither findable with a hand-written mock.** Both are the `external-contract-verification` failure class.

1. **An empty env var silently matched no team.** `.env.example` ships `LINEAR_RA_TEAM_ID=""`. The default chain used `??`, which accepts `""` — so a verbatim `.env` sent `team.key.eq = ""`, matched nothing, printed "No matching issues." and **exited 0**. A false negative in a tool whose only job is reporting open work. Reproduced on the wire, then fixed: blank/whitespace values now collapse to `undefined`.
2. **Duplicate issues were listed as actionable.** Linear's `WorkflowStateFilter.type` documents seven state types — `triage, backlog, unstarted, started, completed, canceled, duplicate`. The filter excluded two, inherited from the `.ps1`. **The RA team has a live `Duplicate` status** (`aec545a9-ad2d-4179-a058-b280b414458d`). Now excluded; `triage` deliberately kept.

**Contract assumptions checked against `@linear/sdk` v92 pulled from npm**, not against reasoning: `PaginationOrderBy` = `createdAt`/`updatedAt` only (so the `.ps1`'s `orderBy: priority` was always invalid); `IssueFilter.team: TeamFilter`; `TeamFilter.key`/`.id` filterable; `StringComparator` has `eq`/`in`/`nin`. Priority `0=None … 4=Low` confirmed twice — MCP tool schema and live issue data.

**Decision: base is `main`, not `sandbox`.** `.claude/agents/pr-creator.md:24` defaults to `--base sandbox`, which assumes you branched off sandbox. This branch did not. Following that default blindly produced an unreviewable, conflicted PR.

**Decision: `linear-query.ps1` left in place.** It still carries both bugs. Not removed — out of scope, and removing a file someone may depend on is not this PR's call.
