## 4. BLOCKER — `origin/main` cannot install

**MEASURED, pristine worktree at `4e3970d6`:**
`corepack pnpm install --frozen-lockfile` → **exit 1**,
`ERR_PNPM_OUTDATED_LOCKFILE — pnpm-lock.yaml is not up to date with package.json`.

Cause: Dependabot #2030 bumped 30 packages, updating `package.json` and
`package-lock.json`. It does not know `pnpm-lock.yaml` exists, because its
`package-ecosystem: "npm"` config resolves to the npm lockfile. Every workflow runs
`pnpm install --frozen-lockfile`.

**This is a consequence of PR #2031 adding a second lockfile.** Owned, not deflected.

Per the brief's own rule ("if either is non-zero, that is the answer — stop"),
`tsc` and `pnpm build` were **NOT RUN on pristine main**: nothing downstream of a failed
install is meaningful.

**It recurs every Monday** until the repo has one lockfile. `.github/dependabot.yml` now
carries a warning naming the failure, the one-line recovery
(`corepack pnpm import && corepack pnpm install --frozen-lockfile`) and the structural
fix. The structural fix — delete `package-lock.json` so Dependabot maintains the pnpm one
— is a repo-wide call and was deliberately NOT made unilaterally.
