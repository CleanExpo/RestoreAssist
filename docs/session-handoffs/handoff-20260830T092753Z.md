## 3. Decisions locked + what shipped

**Gates land last in a stack; the code they judge lands first.** The first split put `check:a11y`, `check:gst-callers` and `check:floorplan-custody` in level 1 and their subjects in levels 4-5. A gate that runs before the code it judges cannot pass. `package.json` moves with the gates, because it *declares* them.

**A base retarget does not run CI.** `pr-checks.yml` fires on `types: [opened, synchronize, reopened]`; GitHub emits `edited` when a base changes. Every stacked PR retargeted to `main` sits at `mergeable_state: clean` **with no Quality Checks run at all**. Merging on that is merging on a tick that never existed. The fix used here was to rebase each level onto the new `main` and push — a real `synchronize`, not an empty commit.

**Validate against the merge-tree result, never a two-point diff.** `git diff main..branch` reported 163 files; the true delta was **139**. A naive `git checkout branch -- files` split silently reverted `main`'s independent gains — it dropped `script:linear-query` from `package.json` on the first attempt. The stack was rebuilt against `git merge-tree --write-tree`.

**A PDF font must fail loud when its asset is missing.** Falling back to a WinAnsi standard font would silently reintroduce the macron bug in the one environment where the asset failed to deploy — production. `lib/resources.ts` guards its runtime read with `existsSync` and returns empty; that tolerance is not copied.

## 7. Deferred + open questions

1. **`check:a11y` never ran in any local validation this session, and a claim was made that it did.** My gate runner extracted steps with the regex `npm run [a-z:-]+`; `a11y` contains a digit, so the character class dropped it silently — no error, no skip line. It was the only step missed, and it was missed every time. The `pass npm run check:a11y` line in #2098's body is therefore unfounded; the gate did run in CI on #2095 and #2097 and passed, so the code is fine, but the local claim was not evidence. **Any future gate runner must diff its captured step list against the workflow's declared list and fail if they differ.** A gate that cannot fail is not a gate — this is the third instance of that pattern in four handoffs.
2. **`pr-checks.yml` runs no CI on a base retarget.** Adding `edited` to its `types:` list is a two-line change and would close the trap described in §3. Not done here — it is infrastructure, and this session had no mandate for it.
3. **Finish the PDF font work.** `lib/pdf/fonts.ts` and the assets are on `claude/portal-pdf-unicode-font`. Remaining: wire the five generators, add an `outputFileTracingIncludes` entry so the asset reaches serverless bundles, add a CI gate asserting it is present and loadable, add `@pdf-lib/fontkit` to `package.json` (it was installed `--no-save` only), write tests, and visually check five document layouts. **The tax invoice is the sharpest of the five** — a legal document that currently cannot be issued to a customer with a macron in their name.
4. **Three CodeRabbit findings on `main` remain unread by anyone**, listed in §5. Each needs behaviour changes with regression tests in custody and invoicing code.
5. **Test files sit outside the type-checked project.** Four test files were missing a *required* field while `tsc -p tsconfig.json` reported zero errors; the omission surfaced only at runtime. A tsconfig question, deliberately not chased inside #2100.
6. **Thirty dead branches need a human.** SHAs in §6. GitHub auto-deletes a head branch on **merge** only — branches whose PRs were *closed*, and branches pushed with no PR, accumulate forever. That is the mechanism behind the pile-up and it will not stop on its own.
7. **Do not run a build or a branch switch while a test suite is running in the same working directory.** A level-2 unit run reported 10 failures across 4 files; all four were level 3/4 files, and the cause was a `git checkout` performed mid-run. Re-running those four files against `origin/main` gave 47/47 pass. Separately, a stale `.next` poisons the next branch's type-check with phantom `TS2307` errors for routes that have not arrived yet. Both are one-working-directory problems; use a worktree.
8. **The continuous Linear loop still returns nothing actionable at Urgent priority.** Unchanged from the previous three handoffs — all five gated Urgent issues target `CleanExpo/skills-library`, a different repository. Not a gate defect; a scope decision for the owner.
