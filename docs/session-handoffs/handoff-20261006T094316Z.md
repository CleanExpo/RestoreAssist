## 3. Decisions locked + what shipped

**Shipped — RestoreAssist #2067 (`768b472`).**

- **D2-paywall-tests was test isolation, not a webhook defect.** The gate runs
  `app/api/webhooks/stripe/__tests__/checkout-completed.test.ts` **twice against
  one Postgres** — once in B3's whole-suite run (`release-gate-score.ts:186`),
  again for D2 (`:810`). The test randomised the user's email but hardcoded the
  Stripe IDs. Both `User.subscriptionId` **and** `User.stripeCustomerId` are
  `@unique`, and one `UPDATE` writes both, so fixing only the subscription ID
  would have moved the violation to the customer index. No production code changed.
- **F2's P1 check was relaxed, but bounded.** `docs/SUPPORT_SLA.md` has never
  offered an unconditional `<=1 h`; the owner chose to relax the gate rather than
  commit to 24/7 cover. The degradation must now be stated and no worse than 2 h.
  An unstated or 8 h fallback still fails.
- **`markdownSection` was treating a `#` comment inside a fenced code block as a
  heading.** This is the one to remember. It truncated the runbook's
  "Build + upload" section to 186 characters and zero table rows, and F2 reported
  it as a non-operational section when nothing was wrong with the document.
  Section parsing and `headingCount` are now fence-aware.

**Shipped — CARSI #855 (merged 09:37:10Z) and #856 (merged 09:55:42Z).** Footer
link plus a render test; #856 carried the test refactor that #855's squash merge

**Two near-misses in my own verification, recorded so they are not repeated.**

1. **A positive control that silently proved nothing.** To check the CARSI test
   failed without the fix, I restored `HEAD~1` — which by then was the commit
   carrying the fix. The suite passed and looked like the test was vacuous. The
   base has to be `origin/main`: 8 failed, then 8 passed. Adding a commit
   invalidates a control that references `HEAD~n`.
2. **I twice reported a state from a snapshot taken too early.** I said the
   overview section had no `id` (I had grepped `components/landing/home/` and
   missed `concepts/`), and I said CARSI CI was not validating the change (the
   real checks had simply not started yet). Both were corrected in-session.
