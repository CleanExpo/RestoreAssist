## Open risk — needs a founder call, not a code change

`app/api/portal/auth/reset-password/route.ts` sets a new password keyed **only** on
knowing the account email — no emailed verification code — then mints a 30-day portal
JWT. One unauthenticated POST is a full homeowner-portal takeover: the victim's reports,
evidence and PDFs, plus write access to `COST_ESTIMATE` / `SCOPE_OF_WORK` approvals. Rate
limiting does not help; the attack needs one request.

The route's own comment records this as a deliberate product decision, so I did not
change it — that is a product change, not a scanner change. It is now recorded as an open
weakness in `docs/security/route-safety-backlog.md` and carried as a visible baseline
entry so it cannot silently disappear again.
