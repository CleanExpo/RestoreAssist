## 3. Decisions locked + what shipped

**The gate over-blocks by design, and the file says so.** A wrong skip costs one cycle and a human notices. A wrong dispatch lets an agent rotate a secret, migrate production, spend, or merge to main (RULES.md 29–33). The errors are not symmetrical, so an ambiguous phrase is treated as gated. This is written into `lib/linear-loop/owner-gated.ts`, not just decided.

**Patterns are extended from live misses, never from guesses.** Every pattern carries a comment naming the issue that motivated it. This rule is stated in the file and was applied against my own instinct in round 3 — see RA-7256 below.

**RA-7256 was deliberately left ungated.** It is the fourth Urgent P0 and it still scores `open`. It carries no wording the gate can read; on reading it, its constraint is operational (*do it in a worktree when no agents are running*), not a human-authority gate. Inventing a pattern to catch it would have been guessing.

**The over-block cost is measured, not assumed.** The first draft of the "filed deliberately unpatched" pattern gated `"Insurer filed the dispute; we have not patched the estimate yet."` and `"The tech filed a report rather than patching the wall himself."` — *filed* and *patched* are ordinary restoration vocabulary. Candidate patterns are now probed against a 16-sentence false-positive corpus **before** the source file is touched, and both sentences are pinned as tests.

**Every regression test is run against the unfixed code first.** A test never observed to fail has not been shown to guard anything. Across rounds 2 and 3, 8 of 9 new gating tests failed against their pre-fix code; the ones that passed both ways are the anti-false-positive guards, which is correct.

**The missing-key error message must not mention the MCP connector.** An earlier version told users to "reconnect the Linear MCP connector and use that instead". The connector authenticates Claude's tools over OAuth; it exports nothing to a shell process. The message was actively misleading and was corrected in #2083 after the user pushed back — they were right and I was wrong to keep raising the caveat.
